## 这是什么

一本可以照着敲、照着判断的操作手册。全书 19 个操作节点（O1–O19）统一用「八段式」结构：

> 解决什么问题 → 产出什么 → 最小可跑通 → 逐步扩展 → 怎么用 → 坑 → 实操练习 → 自我检验

内容主线是一条**五阶段门控**工作流，每个阶段不通过验收就不进下一阶段：

| 阶段 | 内容 | 对应节点 |
| --- | --- | --- |
| 一 · 确认目标与归属 | 授权范围、WHOIS/备案、DNS 与历史解析 | O1 / O2 / O3 |
| 二 · 资产发现 | 子域枚举、证书关联、空间测绘、旁站 C 段、CDN 与源站 | O4 / O12 / O9 / O15 / O10 |
| 三 · 资产刻画 | 探活指纹、端口服务、WAF 识别 | O5 / O6 / O11 |
| 四 · 内容与泄露面 | 目录与敏感文件、搜索引擎 hacking、JS 与接口、代码凭据、移动端入口 | O7 / O8 / O13 / O14 / O17 |
| 五 · 组织与时间线 | 人与组织、变更时间线、（仅实验室）内网 | O16 / O19 / O18 |

除了工具命令，还包括三件容易被跳过、但决定产出的东西：

- **资产表与证据规范**：字段定义、如何把工具输出变成带 `next_action` 的决策行
- **五维评分排序**：不再靠感觉决定「先打哪个」
- **限速与停手条件**：什么时候必须停下来问客户

## 怎么读

不要从头读到尾再动手。信息收集是肌肉记忆型技能，看十遍不如跑一遍。三条路线见正文 **0.1 这本手册怎么用**：

| 你的情况 | 建议路线 | 时间 |
| --- | --- | --- |
| 完全新手，没碰过 Linux 工具 | 0.6 前置知识 → 第 1 章 → O3 → O4 → O5 → O7 | 7 天 × 2h |
| 会基本命令，想系统学 | 0.3 → 第 1 章 → 第 2 章 → 第 3~6 章顺序读，每条都做练习 | 4 周 |
| 有经验，只想补短板 | 直接跳章节；第 8 章（信息→打击面）与第 11 章（排障）建议都读 | 按需 |

## 使用前提（不是免责声明，是操作前置条件）

正文 **0.3 法律与边界** 与 **0.4 三条铁律** 是执行这些命令的前提：

- **只在有书面授权的范围内操作**。authorization 缺失时，后面任何一条命令都不要执行。
- **归属先于发包**：同一 ASN、同一证书、同一子公司都不等于在授权范围内，必须逐个确认。
- **最小化与限速**：证明「存在」即可，不拖库、不上传、不持久化；被拦就停，不加大 payload。
- **敏感数据只判价值不下全量**：命中配置文件/凭据先看内容，不批量下载。

## 快速开始

```bash
git clone https://github.com/D4C-wof/info-gathering-handbook.git
cd info-gathering-handbook

# 1) 先验环境：工具是否装全、有没有版本撞名
bash scripts/check-tools.sh

# 2) 打开正文，按 0.1 的三条路线之一开始
#    完全新手：0.6 前置知识 → 第 1 章 → O3
```

`scripts/recon.sh` 是流水线骨架，**只做收集、不做利用**，并且在 S3 之后强制停下等你人工确认 `targets.txt`——归属判定刻意不自动化：

```bash
bash scripts/recon.sh example.com ./out      # 仅对已授权目标
```
